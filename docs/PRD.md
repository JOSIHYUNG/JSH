# JSH Second Brain 제품 요구사항 정의서

- 문서 상태: Reviewed / implementation-aligned baseline
- 문서 목적: 개인 지식 자료를 저장·연결·탐색·질답하는 제품의 사용자 경험과 기능 범위를 정의한다.
- 대상 릴리스: 개인용 MVP
- 작성일: 2026-07-29
- 최종 역검증: 2026-07-30
- 검토 반영: 의도 정합성·범위·사용자 흐름·현재 구현 연결·디자인 접근성

## 1. 제품 요약

JSH Second Brain은 흩어진 개인 메모와 업무자료를 한곳에 모으고, 자료 사이의 개념적 연결을 시각화하며, 필요할 때 근거가 붙은 답변으로 다시 꺼내주는 개인용 지식 탐색 서비스다.

사용자는 자료를 붙여 넣거나 업로드한다. 서비스는 자료를 문서와 청크로 나누고, 제목·요약·키워드·개념·관계를 추출해 저장한다. 사용자는 지식 그래프를 직접 탐색하거나 `AI에게 질문`하고, 키워드·문장·질문에 대해 관련 근거 최대 3개와 함께 정리된 답변을 확인한다.

제품의 핵심 가치는 “무엇을 저장했는지 기억하지 않아도, 관련 지식의 맥락과 근거까지 함께 찾게 하는 것”이다.

## 2. 대상 사용자와 문제

### 2.1 대상 사용자

주 사용자: 혼자 자료를 축적하는 개인 지식 노동자·연구자·기획자.

특징:

- 짧은 메모부터 긴 보고서와 업무자료까지 다양한 길이의 텍스트를 지속적으로 만든다.
- 자료가 파일, 메모, 문서 등 여러 위치에 흩어져 있다.
- 키워드를 정확히 기억하지 못한 채 “그때 읽은 내용”을 찾는 경우가 많다.
- AI가 자신의 지식을 바탕으로 요약·비교·판단을 돕길 원하지만, 신뢰할 수 있는 지식 기반이 정리되어 있지 않다.
- 여러 사용자가 협업하거나 권한을 관리할 필요는 현재 없다.

### 2.2 핵심 문제

#### 문제 A: 저장은 되지만 다시 찾기 어렵다

자료가 많아질수록 파일명·폴더·정확한 키워드에 의존한 검색은 약해진다. 사용자는 어떤 문서에 답이 있는지보다, 자신이 기억하는 개념·상황·질문으로 찾고 싶다.

#### 문제 B: 자료 간 관계가 보이지 않는다

각 문서는 단독으로 존재하고, 같은 인물·조직·기술·사건이 여러 문서에 반복되어도 연결을 발견하기 어렵다. 사용자는 문서 목록보다 지식의 구조와 주변 맥락을 보고 싶다.

#### 문제 C: AI에게 물어볼 기반이 없다

일반 AI에게 질문하면 개인 자료를 충분히 반영하지 못하거나, 어떤 자료를 근거로 답했는지 확인하기 어렵다. 사용자는 자신의 자료에 근거한 답과 원문으로 이동할 수 있는 출처를 필요로 한다.

#### 문제 D: 자동 분석을 완전히 신뢰하기 어렵다

AI가 추출한 개념과 연결에는 오류가 있을 수 있다. 자동화는 필요하지만, 사용자가 무엇이 추출되었는지 확인하고 잘못된 연결을 발견할 수 있어야 한다.

## 3. 제품 목표와 비목표

### 3.1 목표

1. 자료 1개를 추가하는 데 걸리는 인지적 부담을 최소화한다.
2. 사용자가 저장 자료의 전체 구조를 3D 그래프로 빠르게 파악하게 한다.
3. 정확한 키워드를 몰라도 개념과 문장으로 관련 자료를 찾게 한다.
4. 질문마다 관련 근거를 최대 3개 보여 주고 답변에서 출처를 식별 가능하게 한다.
5. AI 분석 결과를 사용자가 원문과 비교하여 신뢰할 수 있게 한다.
6. 혼자 사용하는 로컬 서비스에 맞게 단순한 진입과 관리 경험을 제공한다.
7. 하나의 대화 안에서 후속 질문의 맥락과 매 turn의 근거를 이어서 제공한다.

### 3.2 비목표

- 회원가입, 로그인, 사용자 초대, 권한 관리
- 여러 사용자의 지식 공간 공유
- 메일·푸시·외부 알림
- 결제·구독·사용량 과금 화면
- 문서 편집기나 프로젝트 관리 도구로의 확장
- 자동으로 사실 여부를 판정하거나 전문가 검증을 대체하는 기능

### 3.3 사용 전제와 책임 범위

- 계정 없이 한 명의 사용자가 자신의 로컬 환경에서 사용한다. 공유·동기화·권한 관리는 제공하지 않는다.
- 원문과 분석 결과는 사용자가 소유·관리하는 개인 자료로 취급한다. 외부 AI 서비스로 전달될 수 있는 범위와 삭제 결과를 첫 사용 전에 알린다.
- AI 답변은 저장된 자료를 빠르게 다시 찾고 정리하는 보조 수단이다. 원문과 근거를 확인하지 않은 답변을 사실 판정이나 전문적 의사결정의 대체물로 제시하지 않는다.

## 4. 제품 원칙

### 원칙 1. 탐색이 입력보다 앞선다

첫 화면은 빈 질문 입력창만 보여주는 대신 현재 지식의 구조를 함께 보여준다. 사용자는 질문하지 않아도 “무엇이 쌓여 있는지”와 “어디가 연결되어 있는지”를 볼 수 있어야 한다.

### 원칙 2. AI 결과보다 근거가 먼저다

답변은 단독으로 보여주지 않는다. 답변을 만든 상위 근거 청크 최대 3개, 각 청크가 속한 원문 문서, 해당 문서 안의 위치로 이어지는 경로를 함께 제공한다. 같은 문서에서 여러 청크가 선택되면 참고 문서 링크는 중복 표시하지 않는다.

### 원칙 3. 자동화하되 숨기지 않는다

분석과 저장은 자동으로 진행하지만, 추출된 제목·요약·개념·연결을 분석 과정에서 보여준다. 사용자가 언제든 원문과 결과를 비교할 수 있어야 한다.

### 원칙 4. 복잡한 구조는 단계적으로 노출한다

처음부터 모든 청크와 관계를 보여주면 그래프가 노이즈가 된다. 기본 화면은 문서와 개념 중심으로 시작하고, 사용자가 선택한 문서에서 청크와 세부 관계를 확장한다.

### 원칙 5. 확신이 없는 답은 모른다고 말한다

관련 근거가 부족하면 억지로 답하지 않는다. “관련 자료가 부족합니다”와 “추가하면 좋은 자료”를 보여준다.

## 5. 핵심 사용자 경험

### 5.1 주요 객체

사용자가 화면에서 이해할 수 있어야 하는 객체는 다음과 같다.

| 객체 | 사용자 관점의 의미 |
|---|---|
| 문서 | 사용자가 추가한 하나의 자료 |
| 청크 | 긴 문서에서 검색·근거로 사용되는 문서의 일부 |
| 개념 | 여러 문서에서 반복되거나 의미 있는 사람·조직·기술·사건 등 |
| 연결 | 문서·청크·개념 사이의 관계 또는 유사성 |
| 대화/질문 기록 | 대화 안의 질문·답변 turn과 당시 답변 근거 |

### 5.2 개념 분류

개념은 아래 13개 분류 중 하나를 갖는다. 화면에서는 분류마다 색상·아이콘을 다르게 표시하고, 상세 화면에서는 분류명을 그대로 보여준다.

| 분류 | 정의 |
|---|---|
| organization | 정부기관, 기업, 군·연구기관, 대학, 부서, 국제기구 |
| organization_unit | 사령부, 부대, 연구소, 부서 등 상위 조직에 속한 단위 |
| person | 인물, 연구자, 정치인, 지휘관, 저자 |
| country | 국가, 국가 그룹, 동맹 |
| region | 도시, 주·도, 지역, 전역, 해역, 국경 |
| place | 기지, 공항, 항구, 시설, 특정 장소 |
| technology | 기술, 알고리즘, 소프트웨어, 통신·센서 기술 |
| equipment | 무기, 차량, 항공기, 함정, 드론, 센서, 장비 |
| system | 방어체계, 정보체계, 무기체계, 운영체계 |
| project_program | 사업, 프로젝트, 개발 프로그램, 조달 프로그램 |
| policy_law | 정책, 법률, 규정, 지침, 교리 |
| event | 전쟁, 분쟁, 작전, 회의, 사고, 발표, 시험 |
| document | 보고서, 논문, 법안, 공식 문서, 데이터셋 |

개념은 최소한 다음 정보를 가진다.

- 대표명: 화면과 검색에 우선 사용하는 이름
- 영문명: 대표명의 영어 표기 또는 원문 표기
- 약어: 원문에 있거나 널리 사용되는 약어
- 분류: 위 13개 중 하나
- 짧은 설명: 한두 문장 이내
- 출처 청크: 어떤 자료의 어느 부분에서 추출되었는지
- 연결된 문서 수와 청크 수

한글명·영문명·약어 중 하나가 기존 개념과 일치하면 새 노드를 만들지 않고 기존 개념에 연결한다. 이름이 비슷하지만 동일하다고 확정하기 어려우면 자동 병합하지 않고 “유사 개념”으로 제시한다.

## 6. 사용자 여정

### 여정 A: 첫 방문

1. 사용자가 서비스에 접속한다.
2. 상단에 제품명, 자료 추가, `AI에게 질문` 입력창과 실행 버튼을 본다.
3. 중앙에는 저장된 지식의 3D 그래프가 보인다.
4. 저장된 자료가 없으면 빈 그래프 대신 “첫 자료를 추가하면 지식의 구조가 나타납니다”라는 안내와 자료 추가 버튼을 보여준다.
5. 자료가 있으면 문서 노드·개념 노드·연결선을 보고 회전·확대·이동할 수 있다.

### 여정 B: 자료 추가와 자동 분석

1. 사용자가 `자료 추가`를 누른다.
2. 모달에서 `텍스트 입력` 또는 `파일 업로드` 방식을 선택한다.
3. 제목은 자동 제안되며 사용자가 수정할 수 있다.
4. 사용자가 분석을 시작한다.
5. 모달 안에서 다음 진행 단계가 순서대로 표시된다.
   - 자료 읽기
   - 긴 자료 나누기
   - 제목·요약·키워드 추출
   - 개념 추출 및 기존 개념과 병합 판단
   - 문서·청크·개념 연결 생성
   - 저장 완료
6. 진행 중인 결과가 만들어지는 순서대로 화면에 나타난다. 결과가 일부 먼저 도착해도 사용자는 현재 단계와 남은 단계를 알 수 있다. 분석 중 모달을 닫으면 원문은 임시 보관되고, 완료 전에는 그래프와 질문 결과에 노출하지 않는다.
7. 완료되면 대표 제목, 핵심 내용, 개념 목록, 연결된 기존 개념, 원문 미리보기를 보여준다.
8. 사용자가 별도 저장 버튼을 누르지 않아도 분석 완료 결과가 자동 저장된다.
9. 저장 완료 후 모달을 닫으면 그래프가 갱신되고 새 자료를 중심으로 이동할 수 있다.

### 여정 C: 그래프 탐색

1. 사용자가 그래프를 회전·확대·이동한다.
2. 노드에 마우스를 올리면 이름·분류·연결 수를 간단히 확인한다.
3. 노드를 클릭하면 오른쪽 상세 패널이 열린다.
4. 문서 노드에서는 제목·요약·키워드·원문 미리보기·청크 목록을 확인한다.
5. 개념 노드에서는 개념 설명·동의/대체 명칭·연결된 문서·관련 청크를 확인한다.
6. 관련 노드 목록에서 다른 노드를 클릭하면 그래프 중심과 상세 패널이 함께 이동한다.
7. 청크를 클릭하면 원문 문서에서 해당 부분이 강조된 상태로 열린다.

### 여정 D: AI에게 질문하고 답변 확인

1. 사용자가 `AI에게 질문` 입력창에 키워드·문장·질문을 입력한다.
2. 첫 질문을 실행하면 대화가 생성되고, 이후에는 같은 화면에서 후속 질문을 입력한다.
3. 후속 질문은 이전 완료 turn의 질문·답변을 참고해 독립적인 검색 query로 변환된다.
4. 매 turn은 전체 지식에서 관련 청크를 최대 3개 새로 검색하고, 답변은 현재 turn의 근거만 citation으로 사용한다.
5. 답변 본문은 `[근거 1]`, `[근거 2]`처럼 근거를 식별할 수 있게 표시한다.
6. 각 답변 아래에는 실제로 사용된 근거 청크와 중복 제거된 참고 문서 링크가 표시된다.
7. 근거 청크를 선택하면 원문에서 해당 위치가 열린다.
8. 대화의 모든 질문·답변과 각 turn의 근거는 자동 저장된다.

### 여정 E: 대화 기록 재방문

1. 사용자가 대화 기록 패널을 연다.
2. 최근 대화를 제목·마지막 질문·turn 수·최근 시각순으로 확인한다.
3. 대화를 선택하면 당시의 질문·답변·turn별 근거를 다시 본다.
4. 원문이 삭제되거나 재분석된 경우에는 snapshot과 현재 문서 상태의 차이를 표시한다.
5. 현재 대화에서 후속 질문을 이어가거나 특정 turn을 다시 실행할 수 있다.
6. 새 UI에서는 대화 전체를 삭제한다. 기존 단일 질문 삭제 API는 호환성을 위해 유지한다.

## 7. 주요 화면

### 7.1 홈 / 지식 우주 화면

목적: 저장된 지식의 상태를 한눈에 보고 바로 탐색·질문·추가를 시작한다.

구성:

- 상단 바: 제품명, 자료 추가, 대화 기록, 설정/상태
- 질문 영역: 새 질문·후속 질문 입력, `AI에게 질문` 실행 버튼, 새 대화
- 그래프 영역: 전체 화면의 중심. 문서와 개념의 3D 구조 표시
- 그래프 컨트롤: 회전·확대·이동 안내, 초기화, 전체 보기, 선택 노드 중심 이동
- 필터: 개념 분류, 문서/개념/청크 표시 여부, 연결 강도, 최근 추가 기간
- 범례: 문서, 청크, 개념 유형별 색상과 의미
- 보조 영역: 최근 추가 자료와 최근 질문 기록에 빠르게 접근
- 선택 패널: 선택 노드 상세, 관련 노드, 원문 이동

빈 상태:

- 그래프 중앙에 짧은 설명과 `첫 자료 추가` 버튼
- 질문 기능은 비활성화하지 않고 자료가 없어 관련 답변을 만들 수 없다는 메시지를 제공

### 7.2 자료 추가 모달

모달은 입력부터 분석·저장까지 한 흐름으로 이어진다.

#### 입력 상태

- 탭: `텍스트 입력` / `파일 업로드`
- 제목 입력: 자동 제안값을 기본값으로 표시하고 수정 허용
- 본문 입력: 길이 표시, 빈 값 검증
- 파일 업로드: 지원 형식·최대 크기·파일명 표시
- 외부 AI 처리 안내: 자료가 분석·질답을 위해 외부 AI 서비스로 전송될 수 있음을 표시
- 액션: 분석 시작, 닫기

#### 분석 상태

- 현재 단계와 전체 단계
- 진행 중인 작업의 설명
- 추출 결과가 누적되는 실시간 패널
- 추출 제목, 핵심 내용, 키워드, 개념, 연결 관계
- 새로 발견된 개념과 기존 개념에 연결된 개념 구분
- 오류 발생 시 실패 원인, 재시도, 임시 결과 확인
- 액션: 분석 취소, 다시 분석

#### 완료 상태

- 저장 완료 표시
- 문서 요약, 주요 개념, 연결된 자료 수
- `그래프에서 보기`, `문서 열기`, `닫기`
- 자동 저장된 결과를 되돌릴 수 있는 짧은 `실행 취소` 액션

### 7.3 문서 상세 패널/페이지

- 제목, 파일명/입력일, 요약, 키워드
- 원문 보기와 청크 목록
- 원문 안에서 선택된 근거 청크 강조
- 연결된 개념 목록
- 연결된 문서 목록과 연결 이유
- `그래프에서 중심에 놓기`
- `다시 분석`, `삭제`

삭제는 확인 단계를 거치며, 삭제하면 문서·청크·문서에서만 사용되던 개념 연결·질문 기록의 근거 표시가 어떻게 바뀌는지 안내한다.

### 7.4 개념 상세 패널

- 개념 대표명, 영문명, 약어, 분류, 설명
- 이 개념이 발견된 청크 목록
- 연결된 문서와 문서 내 위치
- 함께 나타나는 개념
- 유사 개념 제안
- `이 개념으로 질문`, `그래프에서 중심에 놓기`

### 7.5 질문 결과 및 AI 답변 화면

`AI에게 질문` 실행 후 같은 화면에서 답변과 근거 자료를 함께 보여준다. 별도의 검색 모드는 제공하지 않으며, 관련 자료를 찾는 과정은 답변 생성 전에 내부적으로 수행한다.

관련 자료:

- 질문과 실행 시각
- 관련도 순 근거 청크
- 문서 제목, 청크 미리보기, 키워드, 관련 개념
- 결과별 원문 열기

AI 답변:

- 답변 본문
- 근거 표식과 근거 청크 하이라이트
- 실제 사용된 근거 청크 카드 최대 3개와 중복 제거된 참고 문서 링크
- 자료 카드의 문서 링크, 문서명, 청크 위치
- `근거 부족` 또는 `관련 자료 없음` 상태
- 답변 다시 생성, 질문 수정

답변은 근거 자료와 시각적으로 구분하되, 사용자가 어느 문서에서 생성되었는지 한 화면에서 이해할 수 있어야 한다.

### 7.6 대화 기록 화면/패널

- 최근 대화 목록
- 대화 제목, 마지막 질문, turn 수, 최근 활동 시각
- 항목 선택 시 전체 turn과 당시 근거 복원
- 대화 제목 수정, 재시도, 대화 전체 삭제

### 7.7 오류·상태 안내

서비스는 다음 상태를 사용자에게 명시한다.

- 자료 분석 중
- 자료 저장 중
- 관련 자료 찾는 중
- AI 답변 생성 중
- 관련 자료 없음
- 관련 자료가 부족함
- AI 서비스 연결 실패
- 분석 결과가 불완전함
- 삭제 처리 중

기술 오류 코드만 보여주지 말고, 사용자가 다음에 할 수 있는 행동을 함께 제공한다.

## 9. 데이터 처리 규칙

### 청킹 규칙

- 원문은 문서 단위로 보존한다.
- 24,000자를 초과하는 자료는 24,000자 단위로 나눈다.
- 연속 청크 사이에 500자 겹침을 둔다.
- 청크에는 순서와 원문 안의 시작·끝 위치를 부여해 근거 위치를 다시 열 수 있게 한다.
- AI 검색에는 전체 원문을 기준으로 제공하되, 그래프·질문 결과·답변 근거의 표시 단위는 24,000자 청크로 일관되게 사용한다.
- 근거 청크를 선택하면 원문에서 해당 구간을 정확히 강조한다.
- 문서 청크가 2개 이상이면 문서 노드는 청크 노드에만 연결한다.
- 개념 노드는 실제로 발견된 청크에 연결한다.
- 1개 청크 문서도 동일한 계층을 유지해 문서→청크→개념으로 처리하는 것을 권장한다. 기본 그래프에서는 단일 청크를 시각적으로 접어 복잡도를 낮춘다.

### 개념 추출량과 답변 근거

- 청크당 개념 노드 수에는 고정 상한을 두지 않는다. 자료에서 의미 있는 개념과 관계를 최대한 추출하되, 각 개념의 설명과 관계명은 짧게 유지한다.
- 질문 답변은 검색된 근거 청크만 사용해 작성한다. 근거에 없는 내용을 보완해 단정하지 않으며, 필요한 경우 “자료에서 확인되지 않음”으로 표시한다.
- 답변에 사용할 근거는 관련도 순으로 최대 3개다. 같은 문서의 중복 청크는 최소화하되, 관련성이 낮은 자료를 3개로 채우지 않는다.

### 개념 병합 규칙

1. 추출 결과에서 대표명·영문명·약어를 정규화한다.
2. 공백·대소문자·일반적인 구두점을 제거한 비교값을 만든다.
3. 한글명, 영문명, 약어 중 하나가 기존 개념의 정규화값과 일치하면 동일 개념 후보로 판단한다.
4. 분류가 서로 다르면 자동 병합하지 않는다.
5. 같은 분류라도 이름이 부분적으로만 비슷하면 유사 개념으로 남긴다.
6. 병합된 모든 출처 청크를 보존한다.

### 관계 추출 규칙

관계는 가능한 한 짧은 동사/관계명으로 표시한다. 예: `소속`, `사용`, `위치`, `개발`, `참여`, `발생`, `관련`, `언급`.

- 근거 청크에 관계가 명시되어 있을 때만 강한 관계로 표시한다.
- 단순히 같은 문서에 있다는 이유만으로 강한 관계를 만들지 않는다.
- 의미 유사도만으로 연결할 때는 `유사` 관계로 표시한다.
- 관계마다 출처 청크와 설명을 갖는다.

## 10. 빈 상태·예외·신뢰 경험

### 관련 자료가 없는 질문

“관련 자료를 찾지 못했습니다”를 표시한다. 질문을 바꾸거나 자료를 추가할 수 있는 행동을 제공한다. 자료가 없는데 일반 상식으로 답하는 모드는 제공하지 않는다.

### 근거가 3개 미만인 질문

실제로 관련된 근거만 표시한다. 3개를 채우기 위해 낮은 관련도 자료를 강제로 넣지 않는다. 답변에는 “근거 2개를 바탕으로 정리함”처럼 실제 개수를 표시한다.

### 분석 결과가 의심스러운 경우

추출된 개념에 출처 청크를 붙이고, 사용자가 원문을 열어 확인할 수 있게 한다. AI가 확신하지 못한 개념은 별도 배지로 표시하거나 자동 연결 강도를 낮춘다.

### AI 연결 실패

원문 저장과 로컬 검색이 가능한 상태라면 자료를 보존한다. AI 답변은 생성하지 않고 “분석/답변 서비스에 연결하지 못했습니다”를 표시하며 재시도한다.

### 삭제

삭제 전 대상 문서와 영향을 받는 연결 수를 보여준다. 문서 삭제 후 고립된 개념은 즉시 삭제하지 않고, 연결이 0개인 고립 개념을 다음 그래프 갱신 때 숨기는 것을 권장한다.

## 11. 성공 기준

### MVP 수용 기준

- 사용자가 첫 화면에서 자료 추가를 시작할 수 있다.
- 한 자료를 추가하면 제목·요약·개념·연결 결과를 확인할 수 있다.
- 긴 자료는 원문과 청크 위치가 보존된다.
- 그래프에서 문서와 개념을 탐색하고 노드 클릭으로 원문을 열 수 있다.
- `AI에게 질문`에 키워드 또는 자연어 문장을 입력하면 관련 청크를 확인할 수 있다.
- 질문에 대해 최대 3개의 실제 근거 청크와 문서 링크가 반환된다.
- 답변의 근거를 클릭하면 원문 위치로 이동한다.
- 질문 기록을 다시 열고 삭제할 수 있다.
- AI 실패·빈 결과·분석 실패가 사용자에게 이해 가능한 메시지로 표시된다.
- 다크·라이트 테마 모두에서 본문·문서 원문·그래프 범례를 무리 없이 읽을 수 있고 선택 테마가 재방문 뒤 유지된다.

### 제품 지표

초기에는 정량 지표보다 다음 행동을 관찰한다.

- 자료 추가 완료율
- 분석 결과 확인 후 그래프 탐색으로 이어지는 비율
- 질문 후 원하는 문서/청크를 여는 비율
- AI 답변의 근거 링크 클릭률
- 답변 재생성 또는 질문 수정 비율
- 사용자가 “찾지 못함” 뒤에 자료 추가나 다른 질문을 시도하는 비율
- 잘못된 개념 병합·연결을 사용자가 발견하는 비율

## 14. 추가 결정이 필요한 설계와 권장안

아래 항목은 구현 전에 제품 관점에서 확정해야 한다. 기술 선택이 아니라 사용자 경험과 정책에 직접 영향을 주는 항목만 나열한다.

### 14.1 자료 입력 범위

P0는 붙여넣기·`.txt`·`.md` 등 구조가 단순한 텍스트 자료에 집중한다. 텍스트 추출 가능한 PDF는 P1로 미루고, 이미지 중심 PDF·표·스캔 문서는 그 이후로 둔다. 초기 제품의 핵심은 지식 구조이지 모든 파일 형식 지원이 아니다.

### 14.2 자동 저장과 사용자 승인

자동 저장하되 P2에서 완료 화면에 10초 내 실행 취소를 제공한다. P0/P1에서는 완료 직후 문서 상세의 삭제 기능을 명확히 제공한다.

### 14.3 그래프의 기본 노출 계층

기본은 문서·개념만 표시하고, 문서 선택 시 청크를 확장한다. 청크가 2개 이상인 문서는 문서→청크→개념 계층을 유지하되, 화면에서는 접힌 상태로 시작한다.

### 14.4 관계 표현 방식

P0는 선의 방향과 짧은 관계명을 제공하고, 편집은 개념 큐레이션과 함께 P2로 둔다. 사용자가 관계의 의미를 이해해야 그래프가 장식이 아닌 지식 도구가 된다.

### 14.5 근거 청크와 참고 문서 수

근거 청크는 최대 3개로 하고, 각 청크의 출처 문서는 중복 없이 참고 자료로 표시한다. 관련도가 충분한 근거가 1~2개뿐이면 그 수만 표시한다. 근거가 부족한데 3개를 채우면 신뢰도가 떨어진다.

### 14.6 AI 처리 데이터 고지

첫 업로드 전 명확한 고지와 설정에서 다시 확인할 수 있는 상태 표시를 제공한다. 개인용이어도 원문이 외부 AI 서비스에 전달될 수 있다는 점은 사용자가 알아야 한다.

### 14.7 문서 삭제와 AI 검색 데이터 삭제

사용자가 삭제하면 원문·AI 검색 대상·그래프 연결에서 함께 제거한다. 처리 지연이 있을 수 있으면 삭제 진행 상태를 표시하고, 질문 결과에서는 즉시 숨긴다.

### 14.8 대화 기록 보존 기간

개인용 MVP는 대화를 무기한 보존하고 대화 단위 삭제를 제공한다. 개별 turn 삭제는 context 재계산과 branch 정책이 필요하므로 초기 범위에서 제외한다.

### 14.9 답변의 기본 언어와 명칭

답변은 질문 언어를 따르고, 개념 노드에는 대표 한글명·영문명·약어를 함께 표시한다. 군·기술·조직명은 원문 표기를 잃지 않아야 한다.

### 14.10 데스크톱과 모바일 우선순위

3D 그래프 탐색과 문서 입력이 중심이므로 P0는 데스크톱 우선으로 완성한다. 모바일은 AI 질문·답변·문서 읽기를 우선하고, 그래프는 축소된 탐색 모드로 제공한다.

### 14.11 분석 재실행과 결과 버전

P0/P1은 최신 결과로 갱신하고 과거 질문 근거 snapshot의 변경 상태를 표시한다. 이전 분석 결과와 현재 결과 비교는 P3에서 제공한다.

### 14.12 사용자가 고칠 수 있는 범위

P2에서 개념 숨김·병합·분리·이름·분류와 관계 수정까지 한 묶음으로 제공한다. 사용자의 수정은 다음 분석에서도 우선 보존한다.

### 14.13 로컬 데이터 백업과 복구

로그인·동기화가 없으므로 로컬 디스크 문제로 자료를 잃을 위험이 있다. P5에서 전체 자료·분석 결과·질문 기록의 export/import와 복구 검증을 제공한다. 그 전에는 `backend/data` 백업이 필요함을 운영 문서에 명시한다.

## 15. 검토 반영 결정

### 15.1 검색과 AI 질문의 진입 방식

사용자에게 노출되는 진입점은 `AI에게 질문` 하나로 통일한다. 별도의 `검색` 버튼이나 단순 검색 모드는 제공하지 않는다.

- 입력값은 키워드·문장·질문을 모두 허용한다.
- 사용자가 `AI에게 질문`을 실행하면 서비스가 내부적으로 관련 청크를 찾고, AI 답변·근거 청크·참고 문서를 한 화면에 표시한다.
- 질문형 입력을 자동 실행하지 않고, 사용자가 직접 실행 버튼을 누르게 한다.
- 관련 자료를 찾는 과정은 내부 단계로 처리하며 사용자에게 별도 단계나 용어로 노출하지 않는다.
- 기존의 근거 우선, 최대 3개 근거 청크, 관련 자료 부족 시 단정하지 않기, 질문 기록 저장 권장안을 모두 적용한다.

자료 관리 보완:

- 사용자는 문서 상세 패널에서 제목 또는 원문을 수정할 수 있다.
- 제목 수정은 즉시 반영하고, 원문 수정은 기존 분석 결과를 새 원문 분석 결과로 교체한다.
- 사용자는 분석 중 자료를 삭제 요청할 수 있으며, 원문·그래프·새 질문 대상에서 제거한 뒤 외부 인덱스와 로컬 asset을 정리한다.

## 15.2 탐색형 Agent 전환 추가 요구사항

### 15.2.1 Agent 사용자 경험

사용자는 질문을 보내면 AI가 바로 답하거나 자료 검색·개념 탐색·웹 검색을 선택적으로 수행하는 과정을 순서대로 확인한다. 진행 문구는 간결한 고정 label로 표시하고, 최종 답변에는 local S1..S3와 web W1.. 출처를 구분해 제공한다.

### 15.2.2 실행 제한과 실패 경험

Agent cycle은 최대 30회다. 제한 도달 시 부분 탐색 이력과 중단 이유를 표시하고 불완전 답변을 사실처럼 저장하지 않는다. tool 오류는 재시도 가능한 경우 Agent가 재시도하며, 최종 실패 시 stable error code와 재시도 action을 제공한다.

### 15.2.3 대화 context

현재 질문과 최근 완료된 사용자 메시지 최대 3개 및 각각의 답변만 다음 AI 호출에 포함한다. 대화 요약은 만들지 않으며, Agent가 실행 중 만든 tool trajectory만 해당 run 내부에서 이어간다.

## 16. 구현 적합성 감사

### 16.1 현재 구현 감사

2026-07-30 기준 현재 구현은 P0의 API·DB·파일 저장·구조화 Responses 분석·3D graph·멀티턴 질문·turn별 근거 흐름을 갖췄다. 분석 진행은 SSE 우선/polling fallback, 질문은 202/polling, 문서 CRUD·질문 rerun·대화 rename/delete·근거 range 강조·그래프 focus/filter·테마 전환까지 연결됐다. Vector Store는 로컬 분석 완료와 분리된 degraded-capable 부가 인덱스다.

- 분석 SSE는 stage/progress/terminal 상태만 제공한다. 제목·요약·개념·관계의 누적 preview event와 완료 요약은 P1 잔여 범위다.
- 개념 병합/분리/이름·분류 수정과 관계 수정·숨김은 P2다.
- 문서 재분석은 최신 결과로 교체하며 이전 분석 결과 비교·복원은 P3다.
- 대화 URL 복원은 구현했으며, 문서·개념 panel/filter 복원과 saved graph layout은 P3 이후다.
- 실제 브라우저 visual regression 환경과 분석·검색 품질 평가셋은 P4 잔여 범위다.

기능 완료 표시는 §12의 단계별 완료 기준과 자동·수동 검증 결과를 함께 만족할 때만 한다. 디자인 방향과 화면별 수용 기준은 `docs/03_design_system.md`를 단일 시각 명세로 사용한다.

### 16.2 우선순위 변경 원칙

1. 데이터 손실·근거 불일치·가짜 진행 상태는 시각 polish보다 먼저 수정한다.
2. API/DB 계약이 없는 UI action은 노출하지 않거나 disabled 이유를 표시한다.
3. P1의 신뢰성 기능이 완료되기 전에는 P2의 자동 관계 확장과 장식적 3D 효과를 추가하지 않는다.
4. P3 이후 기능은 기존 P0/P1 데이터와 호환되는 migration 및 snapshot 정책을 먼저 정의한다.
